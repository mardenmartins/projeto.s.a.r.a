Da fabricação à verificação

Uma jornada conectada por uma identidade digital.

O S.A.R.A. — Sistema Automático de Reconhecimento de Autenticidade — foi concebido para atribuir uma identidade individual a cada unidade de produto. Essa identidade conecta o item físico a um histórico digital consultável por QR Code.

Ideia central: em vez de identificar apenas um tipo de produto ou um lote inteiro, o S.A.R.A. propõe que cada unidade tenha seu próprio identificador. Os eventos registrados ao longo da cadeia ajudam a compor a história daquele item e a apontar situações que mereçam conferência.

Fluxo operacional

As etapas do processo

O fluxo abaixo descreve a jornada proposta, desde o cadastro inicial até a consulta feita pelo consumidor. A disponibilidade de cada informação depende dos registros realizados pelos participantes da cadeia.

01

Cadastro do fabricante

O fabricante ou responsável autorizado cadastra o produto no sistema, informando dados como nome, marca, categoria, lote, data de fabricação, local de origem e demais atributos relevantes. O cadastro estabelece a referência digital que será associada à unidade física.

02

Geração da identidade individual

O sistema gera um código exclusivo para a unidade. Esse código funciona como uma chave de consulta do registro digital. A identificação individual é importante porque permite diferenciar duas unidades do mesmo modelo e lote.

03

Aplicação do QR Code

O identificador é convertido em QR Code e aplicado à embalagem ou etiqueta do produto. A leitura direciona a consulta para o registro associado àquele código. A aplicação física deve dificultar remoção, substituição ou reutilização indevida da etiqueta.

04

Distribuição e movimentação

Durante a circulação, os participantes autorizados podem registrar eventos como envio, recebimento, transferência e chegada ao estabelecimento. Cada evento pode conter data, hora, local e responsável, formando uma linha do tempo de rastreabilidade.

05

Conferência no ponto de venda

Antes de concluir a comercialização, o operador consulta o código e confere os dados disponíveis: descrição, marca, lote, origem e situação do produto. Divergências podem ser encaminhadas para análise antes da venda.

06

Registro da venda

Após a confirmação, o PDV registra a comercialização, associando o produto ao estabelecimento, data e horário. No protótipo atual, o status muda para “Vendido”. Em uma implantação real, a integração com o sistema de caixa e os controles de acesso precisariam ser implementados.

07

Consulta pelo consumidor

O consumidor utiliza a câmera do celular para ler o QR Code. A página de consulta apresenta os dados autorizados do produto e sua situação no sistema, permitindo comparar o item físico com as informações cadastradas.

08

Análise de inconsistências

O sistema compara o identificador consultado com o histórico registrado. Reutilização do mesmo código, tentativas repetidas ou eventos incompatíveis podem gerar alertas. O alerta indica uma situação suspeita para investigação, e não uma prova definitiva de falsificação.

Interfaces de acesso

São as telas utilizadas pelos diferentes perfis. Cada perfil deve visualizar apenas as funções e informações necessárias à sua atividade.

Serviços e regras

A API recebe as solicitações, valida permissões, executa as regras de negócio e registra os eventos de forma consistente.

Base de dados

Armazena os cadastros e a sequência de eventos relacionados a cada unidade, com controles para preservar integridade e histórico.

Auditoria e segurança

Uma implantação deve prever autenticação robusta, perfis de acesso, comunicação criptografada, trilhas de auditoria, cópias de segurança e proteção de dados pessoais.

Exemplo prático

Como o sistema pode apontar um QR Code clonado?

Imagine que uma unidade legítima tenha sido cadastrada e vendida em um estabelecimento. Uma cópia da embalagem reproduz o mesmo QR Code. Quando o código é consultado novamente em uma situação incompatível com o histórico, o sistema pode registrar um conflito.

1. Produto original

O código individual foi criado no cadastro e vinculado ao produto legítimo. A venda é registrada no estabelecimento de origem.

2. Código reproduzido

Uma segunda embalagem apresenta o mesmo identificador. O sistema encontra um histórico anterior associado àquele código.

3. Comparação dos eventos

O sistema compara horários, locais e estados disponíveis. Se houver incompatibilidade, registra uma ocorrência para análise.

4. Alerta e apuração

O responsável recebe um alerta e pode verificar o produto, a embalagem, a origem e os registros relacionados antes de concluir qualquer ação.

Importante: QR Code sozinho não impede clonagem.

Um código estático pode ser copiado. A proposta do S.A.R.A. é combinar identificador individual com histórico de eventos e regras de detecção. Para aumentar a segurança em escala comercial, seriam necessários controles adicionais, como etiquetas invioláveis, mecanismos criptográficos, integração com os sistemas dos participantes e monitoramento de padrões de consulta.

Participantes

Quem utiliza e quem se beneficia?

Fabricantes e marcas

Cadastram unidades, geram identificadores e acompanham os registros vinculados aos seus produtos.

Distribuidores e lojistas

Registram movimentações e vendas, além de conferir a situação dos produtos recebidos.

Consumidores

Consultam o QR Code e visualizam informações de procedência disponibilizadas para consulta pública.

O que existe no protótipo

Escopo atual do MVP

O protótipo acadêmico demonstra o conceito por meio de páginas web e armazenamento local no navegador. Ele permite cadastrar produtos de demonstração, gerar identificadores, registrar vendas, consultar códigos e visualizar alertas simulados.

Limitação técnica atual: como os dados ficam no navegador, não há sincronização entre dispositivos ou estabelecimentos. O protótipo não representa uma plataforma de produção e não deve ser utilizado para certificar produtos reais. Uma versão operacional exigiria backend, banco de dados central, autenticação segura e integração com sistemas externos.
